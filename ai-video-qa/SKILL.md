# 🎬 AI 生成影片驗收（ai-video-qa）

服務商各自的 API／prompt 寫法各有一顆 skill；**本 skill 只管「怎麼驗、怎麼不過關就定因」**。

> 📍 **路徑慣例**：文中 `$HERMES_HOME/scripts/` 指你自己的工具目錄；本 skill 自帶的腳本在 `scripts/` 子目錄。
> 端點用環境變數（例 `COMFYUI_URL`）；暫存一律 `tempfile.gettempdir()`。

## When to Use

- 出完影片要自己 QA／交稿前驗收（雲端 i2v、本地影音模型都適用）
- 過渡影片（首尾幀 I2V）出現「物件憑空出現」「動作跳接」「殘影」
- 要驗一批影片的尺寸／fps／幀數是否一致
- 需要把影片內容交給只有靜態視覺能力的工具看（vision）

## 1. 🔴 抽幀密度鐵律

**要看「過渡連不連續」，必須每 10~15 幀抽一張（≥9 幀）。**

曾經抽 4 幀（第 1/41/81/121、每 40 幀）去看一支 121 幀的過渡片，得到「過渡不自然、中間步驟全部缺失」——**這是誤判**：中間的 38 幀全被跳過不看，當然看起來像跳接。

| 抽幀密度 | 能看什麼 | 不能看什麼 |
|:--|:--|:--|
| 每 40+ 幀（3~4 幀） | 首尾對不對、大方向對不對 | ❌ **絕對不能用來判斷連貫性** |
| 每 10~15 幀（8~13 幀） | ✅ 動作是不是連續漸進、有無跳接 | 細節瑕疵 |
| 每 1~3 幀（局部） | 殘影、閃爍、邊緣扭曲 | 整體節奏 |

> 💡 心法：**抽幀密度要跟「你要下的結論」匹配**。要說「過渡不自然」，抽樣證據就得撐得住那句話。

### 🔴 抽幀自身的三個坑（同日三次誤判，不要重犯）

1. **`select` + `tile` 做接觸表只會截到「前 0.5 秒」**：`select` 是「**保留所有符合的幀**」不是抽樣——
   `select='between(t,0.3,5.0)'` 後面接 `tile=4x3`，拿到的是**前 12 個連續幀**（0.3~0.8s），
   不是均勻分佈在 0.3~5.0s。**要均勻取樣就把 `fps=N` 放在 `tile` 前面**：
   ```bash
   ffmpeg -y -v error -t 6 -i X.mp4 -vf "fps=2,scale=520:-1,tile=4x3" -frames:v 1 sheet_A.png   # 0~6s 每 0.5s 一格
   ffmpeg -y -v error -ss 6 -t 9 -i X.mp4 -vf "fps=1.5,scale=520:-1,tile=4x3" -frames:v 1 sheet_B.png # 6~15s
   ```
2. **端點看得到「有沒有出現」，但看不出「動作連不連續、有沒有重複」**：
   ① 判「放箭與收勢沒演到」→ 人看全片：「有搭弓射箭」；② 判「沒有翻滾」→ 實際有低伏翻轉。
   → **「動作有沒有發生／有沒有重複／連不連續」一律交人看**；抽幀在這裡只做兩件事：
   量**規格**（ffprobe）與**動作量數值**（逐幀差、前後段一致性）。
   → 影片類交件前**不要**自己抽幀下「內容」結論再拿它去改 prompt（會白忙、又顯得沒在看片）。
3. 🔴🔴 **「中間那個動作根本沒演」是稀疏抽樣最容易偽造出來的假陰性**（差點把**修好的**片回報成沒修好）：
   情境：首尾幀要「起身前先把擱在桌上的筆拿起來」→ 抽 4 幀（0／40／90／190）問 vision →
   回「**中間缺少拿起的動作畫面**」，讀起來像模型沒演 ✗；改成**每 10 幀抽**（第 30→100 幀）再問 →
   **第 50 幀就拍到她的手伸到桌面接觸筆** ✓、60 幀起筆穩定在手上 ✓ ＝ 動作連續、只是取樣正好跳過它。
   - 機制：中間動作只佔幾格（本例 50→60，約 0.4s）→ 稀疏取樣的兩格**剛好一前一後**＝看起來像憑空出現；
     vision 還會把「兩格之間狀態變了」**推論成**「缺一段動作」，而且講得像事實 ✗。
   - 🔴 規則：**要下「某動作沒做／沒演到／沒連戲」之前，先把關注窗格密集抽（每 10 幀）再判一次**。
     尤其針對**「我剛修好的那支」**——先確認修好了沒，再決定要不要回報失敗：誤報失敗＝對方可能下令重跑＝白燒錢。
   - 對照：**全局盤面**（規格／地板材質／身份一致／首尾 landing）抽 4 幀就夠；**窗格內的動作有無**不夠。
   - 定位法：不要只問「有沒有做」，直接**逐格追蹤那個物件**（「筆在哪裡：桌上／手上／看不到」）→
     哪一格換手一目了然，也順便量到「入到出」的窗格長度。
4. 🔴 **「怪畫面」先排除「那是劇情動作」，不要直接報 glitch**：實測把「某件衣物出現在角色頭頂」判成生成瑕疵，
   對方回「**那是她把衣服脫了拋上去**」——同一個動作在抽幀上長得就是「物件出現在怪位置」。
   → 下「這是 glitch／殘留」之前先自問：**這個怪的狀態有沒有可能是一個動作的結果**（拋、甩、脫、掉落…）；
     排除不掉就交人看全片，**不要拿它當失敗證據去下令重跑**（誤殺＝白燒錢，同第 3 點）。
   - 機制：抽幀**沒有意圖資訊** → 只有「動作連不連續」與「規格」撐得住結論；
     「物件狀態的意圖／正常與否」只能由看全片的人判（與 §5「vision 不是裁判」同族）。

## 2. 抽幀工具鏈（標準動作）

```bash
# 1) 密集抽幀（每 15 幀）——看連貫性用這個
ffmpeg -y -v error -i X.mp4 -vf "select='not(mod(n\,15))'" -vsync 0 f_%02d.png

# 2) 指定關鍵幀（看首／中／尾的姿態，不看連貫性）
ffmpeg -y -v error -i X.mp4 -vf "select='eq(n\,0)+eq(n\,60)+eq(n\,120)'" -vsync 0 k_%d.png

# 3) 拼成接觸表給人目視驗收（4 欄排版、每格下標檔名）——⚠️ 不再丟給 vision，見 §5
```

### 🔴 逐幀差量測：走 ffmpeg 灰階 raw ＋ 純 python，不要靠 PIL／numpy

系統 PIL 裝壞、venv 又沒有 numpy 時（很常見），別在 PIL 上繞。零依賴路線（一次拿到「片內相鄰差」與「首尾差」兩份原料）：
```bash
ffmpeg -v error -y -i X.mp4 -vf "scale=64:94,format=gray" -f rawvideo -pix_fmt gray raw.gray
```
```python
d = open('raw.gray','rb').read(); F = 64*94; n = len(d)//F
fr = [d[i*F:(i+1)*F] for i in range(n)]
adj = [sum(abs(a-b) for a,b in zip(fr[i],fr[i-1]))/F for i in range(1,n)]
print('相鄰差', min(adj), max(adj), '｜末幀vs首幀', sum(abs(a-b) for a,b in zip(fr[0],fr[-1]))/F)
```
- raw 分析檔要落在**真實檔案系統路徑**：native ffmpeg 讀不到 MSYS 的 `/tmp`（不產檔也不報錯）。

## 3. 規格一致性（交稿前必量，不用眼）

```bash
ffprobe -v error -select_streams v:0 \
  -show_entries stream=codec_name,width,height,r_frame_rate,nb_frames,duration \
  -of default=noprint_wrappers=1 X.mp4
```

批次要**逐支印出來比對**（用 `for f in *.mp4` 迴圈 + `-of csv=p=0`），不要只抽一支相信。
實例：餵 832×1216 給首尾幀服務商 → 自動輸出 **1188×1740 / 24fps / 121 幀 / 5.041667 秒**，批次 7 支全一致 → 確認服務商沒偷改比例，可以放心套到狀態機（它靠尺寸對齊）。

### 🔴🔴 姿勢保真 gate：首幀 vs 定稿圖 SSIM ≥0.99

idle（同圖首尾幀微動）除了閉環，還要驗**首幀有沒有忠實地用你給的那張定稿圖**——
若首幀就跑掉了，等於**換了一張圖**上線（姿勢全錯）。
```bash
ffmpeg -y -v error -i X.mp4 -vf "select='eq(n\,0)'" -frames:v 1 f0.png
ffmpeg -y -v error -i 定稿圖.png -vf "scale=594:870" s0.png
ffmpeg -hide_banner -i s0.png -i f0.png \
  -lavfi "[0]format=yuv420p[a];[1]format=yuv420p,scale=594:870[b];[a][b]ssim" -f null - 2>&1 | grep -o "All:[0-9.]*"
```
- 實測 8 支姿勢 idle：**0.9922~0.9931（全過）** → 這個門檻挑得出「換圖」等級的錯。
- 同理驗過渡片：`首幀↔來源母圖` ＋ `尾幀↔目標母圖`（§6「過渡片不能用閉環判」）。

### 🔴 ffmpeg 拼圖／SSIM 的五個坑（配方直接用）

1. **`ssim` 吃不同 pixel format 的輸入會直接失敗**：影片抽出的幀是 yuv→png、母圖 png 常帶 alpha（RGBA），
   兩邊不對盤時 filter 回 `Terminating thread with return code -22 (Invalid argument)`、`Nothing was written into output file`
   —— **看起來像圖不對，其實是格式不對**。正解：**兩邊都先 `format=yuv420p`**。
2. **比對前一定要先對尺寸**：影片 1188×1740、母圖 832×1216 → 兩邊都 `scale=594:870` 再算。
3. **拼圖（接觸表）**：用 `hstack` 逐列拼 → 再 `vstack` 疊列；**不要靠 `-pattern_type glob`**
   （某些 build 回 `globbing is not supported by this libavformat build`）。要固定順序就先把檔案**複製成
   `01_…`、`02_…`** 的編號名再逐個寫進命令，別讓字典序偷偷決定你的格子順序。
   - 要先確認格數 ≥ 輸入數（16 張 → `4x4`）；`tile` 會把不足的格留黑。
   - pitch 寫「左→右、上→下」時**自己回頭核位置對照表**——地圖跑掉比圖醜嚴重得多。
   - 🔴 **`hstack`／`vstack` 要求各輸入尺寸「完全相同」（不是同寬就好）**：`scale=460:-1` 會因來源比例
     差一點點而給出不同高度 → `Invalid argument`（rc 22）、**不產檔也不寫任何東西**。
     拼圖前列一律**寫死兩邊尺寸**（`scale=460:672`），不要靠 `-1`。
   - 🔴 **各排張數不等要先補齊**（一排 7 格、一排 6 格）：少的先 `pad=1729:ih` 補成同寬再 `vstack`；
     用 `color=` 造的黑格若 pixel format 跟真格不同，同樣 rc 22。
4. 🔴 **`-sseof`（抽最後 N 秒）必須放在 `-i` 之前**：`ffmpeg -sseof -0.1 -i X.mp4 -frames:v 1 out.png`。
   放到 `-i` 之後會被當成一般參數 → 直接報錯。**抽尾幀**（新流程拿它當狀態圖／回程首幀）用的就是這條。
   🔴🔴 **但 `-sseof` 對某些片會「抓不到任何幀」而完全靜默**：實測 241 幀 ping-pong 閉環片用 `-sseof -0.04` →
   ffmpeg **不產檔、rc 也回 0** → 下一步 ssim 比對只能回 `All:?`（或讀到上一輪的殘檔）→
   看起來像「12 支全部不合格」，其實是抽幀那一行掛掉。
   → **最穩的抽末幀＝用明確幀號**：`-vf "select='eq(n\,240)'" -frames:v 1 out.png`（N ＝該檔自己的 `nb_frames-1`）。
   🔴 通則：**所有「抽幀／轉檔」步驟後面立刻驗 `os.path.exists(out)`** —— 抽幀失敗不會報錯，只會讓後面的判定全錯。
5. 🔴 **`drawtext` 的 `fontfile` 不能用磁碟機代號路徑**：`fontfile=C:/Windows/Fonts/arial.ttf` 會被 filter parser 的 `:` 吃成選項分隔 → `No option name near '/Windows/Fonts/…`、**不產檔**。作法＝把字型複製到工作目錄旁用相對路徑。同理**標籤文字裡不要有 `:`**。
   ✅ **多版本同場比較圖（A/B/C 接觸表）標準配方**：每版抽**同一個幀號**、各自 tile 成一列、最後 vstack，每列開頭 drawtext 標版本名。
   臉部細節另抽：`crop=448:448:X:Y,scale=448:448:flags=lanczos,tile=3x1`（3 個時間點）—— 加速器把臉弄糊的崩壞，看 full frame 看不出來，**必須裁臉放大才看得出來**。
   🔴 **驗「身份有沒有跑掉」（動作遷移／換裝／多參考圖的片）時，對照圖第一格要塞來源圖本身**：一格原圖、三格成片並排，身份漂移一眼分得出來。**「像不像」不寫進自己的結論，只負責把對照圖做給人看**（§5）。
   🔴 **A/B 的基準不要重跑**：挑一支**已交付的既有片**當 baseline（同 seed／同參考圖／同 prompt 的那支），只跑候選版，省一整套生成。比較前確認兩邊參數一字不差；有改 sampler／shift 就主動聲明「這是第二個變因」。

## 4. 🔴 首尾幀過渡的物件出現陷阱（最難修的一類）

### 🔴🔴 先看這條：本節的病因可用「單張首幀」結構性繞掉

§4 以下所有症狀（家具／道具**憑空生成**、牆面漸變、取景階躍）都源自同一個前提：
**首尾幀是兩張各自生成的圖**。只要該片的動作**不需要精準落到另一張指定圖**，就走
**單張首幀 ＋ prompt 描述動作**（不餵尾幀）——兩端不一致的問題根本不存在；
回程再**取去程尾幀當首幀**（接點由構造保證連續，不必再驗 SSIM）。
實例：整組站姿狀態圖沒拿筆、母圖有筆 → 每支都演成「筆憑空出現」，改用單張首幀後整類消失。

🔴 **「不餵尾幀」≠「首尾給同一張圖」**（實測，靜默失敗）：某些 i2v 節點在**首尾指向同一張圖**時走的是 idle 的
「同圖無縫循環」→ 出來的片**完全不動**，而**規格（尺寸／幀數／無音軌）與首幀 SSIM 全部正常** → 只有抽幀看內容才發現。
**真·單張首幀 ＝ 把 `last_frame` 這個 input 從節點移除**（多數節點的 `first_frame`／`last_frame` 在 `/object_info` 都是 optional）。
→ 因此新流程驗收的**第一項永遠是「它有沒有動」**（逐幀差／動作均值 ≈0 ＝ 失敗），看完才輪到規格與 landing。
**反例仍在**：需要精準 landing 到某張既有定稿圖時才用首尾幀，§4 以下的招才用得上。

**症狀**：首尾兩張圖的「場景物件不同」時（例如首幀站姿沒桌椅、尾幀坐姿有桌椅），
影片中家具會**憑空生成**——第 81 幀冒出桌子、第 121 幀才冒出筆電；伴隨半透明方框殘影、姿勢跳接。

**根因**：模型必須把「尾幀才存在的物件」生出來，鏡頭又不動，它只能原地變出家具。

**正解：讓鏡頭跟拍**
```
她緩緩坐下來、身體重心自然降低、雙腿彎曲、上半身保持挺直，動作自然流暢、速度平緩，
鏡頭跟著她的動作緩慢向下跟拍、始終保持她在畫面中央，她的外觀與服裝完全保持不變、光線與背景保持不變
```
- ✅ 鏡頭跟著主體移動 → 家具是「跟着走進畫面」的，不是原地變出來的
- ❌ 寫「鏡頭固定不動」→ 鏡頭不動，模型只好生家具（**這是最常見的錯因**）
- ❌ **連禁止句都不能寫**：「不要讓桌椅移動」也會召喚桌椅——**提到＝召喚**
- ⚠️ 跟固定鏡頭的動作要用**不同的 prompt 尾綴**；一般動作寫「鏡頭固定不動」、站⇄坐寫「跟拍」——**兩句同時出現會自相矛盾**
- 硬切／剪接只是**備案**，優先平滑過渡

→ 同理適用：姿勢大幅切換、室內↔室外、手中多出物件、服裝部件增減。

## 4b. 首尾幀過渡：末幀對不上的根因 ＋ 回到原點用 3 幀

### 🔴 「沒回到初始畫面」的根因：輸入比例 ≠ 服務商輸出比例
首尾幀服務商**按自己的比例重新取景**，所以即使你餵了正確的尾幀，**末幀也會跟目標圖對不上**。
實例：來源靜圖 832×1216（≈0.684），服務商出 9:16（0.5625）→ 末幀 diff **15.7**。
**修法：餵圖前自己先把圖裁成服務商比例**（背景都是白牆，裁掉零損失）
→ 首幀 diff 14.6 → **4.0**、末幀 15.7 → **5.5**（明顯對上了）。

### 🔴「回到原點」要用 3 幀，不是做兩支
「最後應該是用幾幀模式：`stand → pose → stand`，這樣才會回到初始狀態。」
→ 3 幀一支（首/中/尾）＝ **去＋回**，便宜一半，狀態機才能無縫接回 base。

### 驗收：先量數值，再交人眼
```
首幀 vs base / 中幀 vs pose / 末幀 vs base 的 mean_abs_diff
```
實測：改比例前 14.6 / — / 15.7（不合格）；改後 **4.0 / 6.6 / 6.0**（過）。
**數值是客觀的，可用；「順不順、好不好看」一律交人看。**

### 🔴🔴 修正：「回到原點」不一定用 3 幀，**跳場景的站⇄坐絕對不能閉環**

| 情境 | 做法 | 成本 |
|:--|:--|:--|
| 同場景小幅度姿勢變化 | **只做去程 2 幀 ＋ 倒轉接片**成閉環 → 閉環精度比模型自回更好（末幀 diff 0.94 vs 9.7） | 最省且最準 |
| 同場景、想一支搞定 | 3 幀 `base→pose→base` | 貴但單檔 |
| **站⇄坐（跳場景）** | ❌ **不能用 3 幀、不能做閉環** → 坐下、起身**各自獨立一支 2 幀** | 兩支 |

### 音軌
過渡影片一般不需要聲音。🔴 **音軌留不留看交付對象的 spec**：交付**別人的素材包**照對方 spec（`ffmpeg -i in.mp4 -c copy -an out.mp4` 剝掉再交）；自家用的片可能反而要保留。兩邊不要共用同一套。

## 4c. 🔴 倒轉接片做閉環（0 成本）＋ 兩個必踩的病灶

**作法**：原片（base→pose）＋ **倒轉片** → 就變成閉環（base→pose→base）。純 ffmpeg、**0 成本**。
✅ 適用：同機位小幅度變化（表情、手臂、小幅側身、**待機微動**）
❌ 不適用：大幅度位移（站⇄坐、走位）—— 路徑不會原路折返，倒轉會像倒退走

**樸素版（原片硬接倒轉片）的兩個病灶：**
1. **「頭尾停很久、接起來停更久」** ← 來源片頭尾本來就有靜止段，倒轉後被複製一份
2. **接合處閃爍**

**先量化「到底幾成是停頓」**（32×32 灰階逐幀差，門檻 1.5）：

| 片 | 總長 | 真正在動 | 停頓佔比 |
|---|---|---|---|
| 動作 A | 241 幀 | 77 幀 | 68% |
| 動作 B | 241 幀 | **16 幀** | **93%**（0.7 秒擺好姿勢就凍住） |
| 動作 C | 241 幀 | 177 幀 | 27% |

→ **不剪停頓直接倒轉 = 把死停頓複製兩份**。副產物結論：**去程用 6 秒就夠**（模型常在 1~3 秒內就到達姿勢）

**閃爍的四個來源（要分開修）：**
1. 不同編碼參數的片段**硬 `concat`** → 要同一組參數重編
2. **VFR 時間戳** → 要 `-vsync cfr`（⚠️ 新版 ffmpeg 已移除 `-vsync`，會回 `Unrecognized option 'vsync'` → 換寫 `-fps_mode cfr`；來源本來就是 CFR 時只寫 `-r 24` 即可）
3. 接縫**重複幀**（正片最後一格 ＝ 反轉第一格）→ 反轉段去掉第 0 幀
4. **播放器 `<video loop>` 的黑幀** ← **要在 JS 解**（雙 video 交叉溶解），**不是素材問題**

**工具：`scripts/loop_back_v2.py`**（自動偵測動作區間 → 剪停頓 → 去重幀 → 伸縮對齊 → 同參數重編）
```bash
python3 loop_back_v2.py IN.mp4 --out OUT.mp4 --conform 1188x1740 --frames 121 --fit
```
- `--keep-holds` 保留停頓（對照用）｜`--thresh` 動作門檻（預設 1.5）
- 伸縮係數限 0.5~4x，超出就不硬伸縮（避免鬼畜快慢動作）
- 實測 6 支全部收成 **121 幀 / 5.04s**；動作只 16 幀那支慢放 ×3.81 → 比原「0.7 秒擺完凍住」自然得多

**「閃爍查不出原因」的判斷法**：用桌機播放器（VLC）連續播同一支兩次——
VLC 也閃＝檔案層（回去修編碼／時間戳／重複幀）；**只在網頁播放器閃＝播放層**（去改 JS，改素材永遠改不好）。

## 4d. 待機微動的閉環、SSIM 驗收、conform 坑

**待機微動（idle）有三條路，優先用 A：**

| 路 | 做法 | 成本 | 閉環 |
|:--|:--|:--|:--|
| **A. 本地「同圖首尾幀」** | i2v 節點的 `first_frame`/`last_frame` **接同一顆 LoadImage** → 模型演完自己回錨點 | **0 成本** | **天生閉環** |
| B. 雲端 i2v 只餵 first 幀 | 一般雲端服務的做法 | 服務商計費 | 沒閉環，要另做回程 |
| C. 倒轉接片 | §4c | 0 | 可以，但要先剪停頓 |

實測（本地首支 idle）：**704×1024 / 124 幀 / 5.5 分鐘**；逐幀差 平均 0.063（真的很微）；
**首幀 vs 末幀差 1.67** → 天生幾乎完美閉環。人看完的描述：「**閉上眼睛點了一下頭再回到原來姿勢**」＝這就是「微動 OK」的標準驗收語。

🔴 **生成解析度要先對齊目標比例**：目標 1188×1740 = 0.6828；用 **704×1032（0.6822）** → 後處理零補邊；
用 704×1024（0.6875）→ 被迫補 6px 白邊 → **SSIM 從 0.971 掉到 0.936**（純幾何誤差，不是內容跑掉）。
⚠️ 錨點效應兩面：微動是它的甜蜜點；**大幅度位移（走路/站⇄坐）不能用同圖首尾幀**（會被拉回參考幀）。

**SSIM 驗收（取代 mean_abs_diff）**：
- 為何不用平均差：它被整張亮度主導，看不出「同源」
- ⚠️ **比例/pad 不符會壓低 SSIM**（0.971 → 0.936）→ 驗收前先確認影片比例 ＝ 母圖比例，否則會誤判成「沒回到位」

**循環片尾幀對齊**：把整片逐幀跟第 0 幀比（64×64 灰階差），**在後段找最像的那格當新結尾**。
實測某支 124 幀中第 85 幀最像首幀（差 0.84）→ 切 86 幀版。
但若首/末幀本來就差很小（1.67），切不切差異不大（1.67 → 1.66）——**先量再決定**。

### ⚠️ conform 的 pad 坑（同一晚踩兩次）
```bash
# ❌ 來源比目標寬時爆錯（704×1024 → 高 1740 時寬 1196 > 1188）
-vf "scale=-2:1740,pad=1188:1740:(ow-iw)/2:0:white"   # Padded dimensions cannot be smaller than input dimensions
# ✅ 正解
-vf "scale=1188:1740:force_original_aspect_ratio=decrease,pad=1188:1740:(ow-iw)/2:(oh-ih)/2:white"
```

### 🔴🔴 微動要「有人味」：身體動作必須寫進 prompt，而且不能有「保持不變」的鎖死句

只寫呼吸／眨眼／頭髮擺動的 idle，出來常是**只有頭髮在飄、身體完全鎖死**——人的判語是「**都是頭髮飄揚而已**」（那不是微動，是會呼吸的 JPG）。

- ✅ **明寫身體動作**：`肩膀自然下沉、身體重心緩緩從一側移到另一側、身體微微側傾再回正、手臂跟著身體輕微擺動`
- ❌ **把「她的姿勢與外觀完全保持不變」這類鎖死句拿掉**：它跟動作指令打架，模型選它 → 身體一動不動。
  改用**正面句**「**她始終保持站姿／坐姿**」；要鎖的是「構圖／光線／背景」不是身體。
- 🔴 同族心法：**提到＝召喚**（§4 的家具同理）——不要在 idle prompt 寫「沒有風」去壓頭髮飄，那會把風寫出來。
- 🔴 **不要自己加料**：prompt 逐字沿用既定原文；要加動作就**只加動作**，不要順手綁其他形容詞（尤其別加「不要嘆氣」這類反向提示詞）。
- **判定法**：抽 4 格（母圖／首／中／尾）比**身體輪廓**——肩膀高低、身體中軸、手臂位置、骨盆重心；四項都不變＝身體被鎖死（**頭髮飄不算動作**）。
  ⚠️ 首尾 SSIM／動作幅度**看不出這件事**（頭髮飄與身體微動的數值同級：實測 0.88~0.94 兩種都落這區間）→ 這條只能靠眼，**交人看**。
- 頭髮偶爾飄一段＝模型特性、**可接受**（「室內也是有電風扇的」）→ 不要為它重出。

## 4e. 🔴 首尾幀「背景牆面不同源」→ 影片裡牆會漸變成灰

症狀（原話）：「**後面的白牆陰影處會變，最後突然變成一大塊沒上油漆的灰牆面**」（同一次「其他動作姿勢表情都很棒」→ **內容 OK、只有背景牆壞**）。

**根因**：首尾幀雖然同機位、由同一張母圖差分，但**動作一改，模型會在背景牆上重畫陰影** → 兩端牆面不同源 → 影片把這段差演成「牆慢慢變灰」。

**診斷（可重用）**：量「**尾幀 − 首幀**」的**共同牆面**亮度差（遮罩＝低飽和 `mx-mn<18` 且亮度 >170），逐格（12×18）印出來 → 一眼看出哪一塊牆變了多少。
實測該片：桌子底下那塊 **均差 -11.6、最深 -82、54~56% 的牆面暗超過 10**；全圖均差僅 -2.5。

**解法：把尾幀的牆同步成首幀的牆**
- 只換「**兩張都判定為牆**」的像素（交集）→ 非同步區變動 **0.0**（人物/家具一個 bit 不動）
- 修後：均差 **-0.7**、暗超過 10 剩 **2.4%**
- ⚠️ 這是**素材端**的問題：重跑十次都一樣，**先同步圖再重跑**，不要一直重抽

**連帶**：prompt 尾綴只寫「鏡頭固定不動」不夠 → 要加「**光線與背景保持不變**」（idle 那條本來就有，過渡片常漏）。

## 4f. 🔴🔴 運鏡詞的術語與「跨場景的幾何上限」

**運鏡術語對照（寫錯直接翻車）：**

| 要的效果 | 正確詞 | 寫錯的代價 |
|:--|:--|:--|
| 相機原地**水平**搖（順時針＝往右） | `pans horizontally to the right`（pan right） | 只寫 `rotates clockwise` → 被吃成 **roll**（整張畫面歪掉＝Dutch angle） |
| 相機跟著角色移動 | `tracking / follow shot` | — |
| 相機沿軌道平移、角色與鏡頭**等距** | `moving sideways across the frame at a constant distance from the camera` | 只寫 `walk toward the RIGHT side of the frame` → 角色往**她的左前方**斜走進別的空間 |
| 相機以角色為**軸心**繞著轉 | `the camera orbits around her, keeping her centred in the frame`（orbit／arc shot） | — |

- roll 護欄句（**正述**，不要用否定句）：`The horizon stays level and the frame stays upright throughout.`
- ✅ 已驗證有效：上面那句「**貼鏡頭平面橫移**」真的壓住了斜走 —— 抽幀量到「體型大小全程不變」＝沒有往鏡頭深處走。

**幾何上限（最重要的一條）：首尾幀不是同一個空間時，運鏡詞一律無效。**

- 症狀：不管 orbit／pan 怎麼改，模型都讓角色**往她的左前方走、經過一道牆面，再到桌椅坐下**。
- 機制：模型的**物理連續性優先於運鏡指令**。首幀到不了尾幀（不同空間／不同機位）時，「讓她走過去」是它唯一的合法解，鏡頭指令被整段忽略。
- ❌ 已試 5 版（模型自選斜走／平移／orbit／orbit 加強／整句拿掉走路句）→ **全敗**。同一組首尾幀**不要再調詞、不要再換 seed**。
- **兩條候選出路**：① 換**有內建運鏡控制**的雲端模型；② **重出母圖成同場景同機位** → 同空間內走過去坐下，物理上必然成立。
- 與「母圖與狀態圖必須同一佈置」是同族病根：**兩端圖的幾何不一致時，prompt 修不動**。

**運鏡／位移的抽幀診斷法**（與 §1 不衝突：§1 判「連不連續」要 ≥9 幀；這裡只判「模型用了哪一招」）：
抽 5 格（1.5／3.0／4.5／6.0／7.5s）→ `hstack` 拼成一條 380px 縮圖 → 問「**只講事實**：①每格她的位置（左/中/右）②體型大小有沒有隨時間變小 ③每格背景是什麼 ④最後一格站著還坐著」。
→ **位置有沒有位移、體型有沒有變小**，一眼就能分出「她是走過去」還是「鏡頭在轉」。

## 4g. 🔴 回程片的「憑空復位」：去程端點比基準更鬆時，還原動作要明寫

**不對稱原則（通則）**：同一個變化，**「滑下去／鬆掉／掉下來」是自然的，「自己滑回去／自己歸位」是異常的**。
物理上只有「動作」能還原，而模型只被兩端圖約束、沒被要求演那個動作 → 它會把差異**憑空抹平**。

- **症狀**：去程終點（例：笑的差分）**兩肩都滑落**，回程要回到的基準母圖**只有單肩滑落** → 回程片尾衣服**自己回到肩上**，中間**完全沒有抬手去拉的動作**，而且是**突然跳格**不是漸進。
- **修法**：回程 prompt 把補償動作**寫進動作句**：
  `她收起笑容、嘴角回復淡淡的弧度、接著伸手把滑落到兩肩的外套拉回肩上、手再放回身側，站直。`
  → 換狀態時只改「滑落的那一側／那幾肩」——**左右一律用畫面側當錨點**。
- 🔴 **規則：去程終點只要比基準「更鬆／更亂」，回程就必須為它寫一個還原動作。** 同族：脫下的外套、散開的頭髮、移位的身體、被拿走的道具。
- **判定法**：密集抽幀（每 10~15 幀）追「**那隻手有沒有去拉**」——抽 4 格會剛好跳過這種短動作（§1）；**只有「服裝回到位」不算過關，「有用手的動作」才算**。

## 5. vision 用在影片抽幀上的能力邊界

| 能信 ✅ | 不能信 ❌ |
|:--|:--|
| 姿態／身體朝向、物件存不存在（桌椅/筆電/鞋） | **機構開合**（把打開的筆電說成閉合，連兩次都錯） |
| 動作幅度（手有沒高舉）、視線方向 | 髮型（把高馬尾看成辮子）、材質、左右手 |
| 背景／光線一致性、有無多餘肢體 | 小配件、精細紋理 |

🔴 **不要把 vision 的描述當事實去回報或去改素材**。實例：曾據 vision 說「筆電閉合」要去重抽，對方一句「筆電沒有閉合」就白忙。**造型／機構類細節以人的目視為準。**

### 🔴 縮圖拼圖會系統性誤判「有沒有某個東西」——要下這種結論就用原圖逐張

把十幾格縮到 200~300px 寬拼成一張接觸表，**細節會被磨掉**，vision 不是「不確定」而是**自信地講錯**：
實測一張 330×250 ×6 格的拼圖，它對六格全回「**皆無眼鏡**」——而那六格每一張都戴眼鏡；同一張拼圖還把一個「手上握著的道具」判給錯的手、把有筆說成沒筆。

- 🔴 **規則：「有沒有 X」（配件、道具、頸圈、眼鏡、鞋）的結論，一律用原圖逐張問**。拼圖小圖只用來判「**大方向**」（有沒有位移、體型有沒有變小、色調變不變）。
- 🔴 **拼圖只能拿來當「給人看的接觸表」**——人自己看最快，而且看的是原尺寸脈絡。
- 🔴 **「有沒有動作」也是同一類誤判**：拼圖超過平台寬度被縮小、vision 只看得到其中幾格時，會把**強動作**判成「幾乎靜止」（實測平均相鄰差 **12.07** ＝強動作，vision 回「各格幾乎一模一樣、沒有變化」）。
  → **動作有無一律以數值為準**（平均相鄰差 >3＝明顯、0~1＝靜止）；vision 只用來判姿態／物件／大方向。要拿視覺當補充，就用**每格 640 的 2×2 以內**拼圖，不要長條大圖。

### 🔴 追蹤「手中道具」的抽幀配方（判「什麼時候不見／換手」）

不要只問「有沒有做那個動作」，直接**逐格追蹤那個物件**：
```bash
# 裁上半身局部 ＋ 每 8 幀一格（比全身小圖準得多）
ffmpeg -y -v error -i X.mp4 -vf "select='eq(n\,0)+eq(n\,8)+…',crop=W:0.5H:0:0.15H,scale=210:154" -frames:v 1 …
```
問法：`① 逐格講她的手上有沒有筆、在哪隻手 ② 有沒有一格筆消失／突然出現／換手 ③ 筆是慢慢消失還是突然不見`
→ 這一問法能直接量出「從第幾格起手裡沒了、桌上什麼時候多一支」。
⚠️ 即使裁了局部，**「有沒有」的結論仍要在原圖解析度下複核一次**。

### 🔴🔴 vision 的定位：**客觀技術檢查可以，審美與「哪張最好」不行**

**定案**：vision 做**客觀技術檢查**（人數、朝向、手數、配件在不在、坐姿方向、嘴巴有沒有動）；**判美醜／品質／「哪張最好」一律不許** —— 那些圖與影片**直接交人看**。
→ **數值量測不受限且是首選**：ffprobe 規格、首中末幀 mean_abs_diff、區域色彩差（服裝/背景有沒有跑掉）、膚色比例（自動抓「換成別的服裝」）。

### 🔴🔴 「可不可感」不屬客觀技術檢查——任何「提細節」的後處理，動工前先問觀看媒介

實測代價：8 步＋內建修臉再拉到 2.0MP 升頻（**72.8 分/段、全片約 6 小時**）→ vision 回「變清晰」、
據此推薦；使用者在**手機**上看完：「**手機螢幕看不出差別，以後還是別放大了**」。

- 🔴 規則：**升頻／修臉／二采這類「提細節」的後處理，決定做不做之前先確認最終觀看媒介**（手機／社群平台都會再壓一次，像素級差異在壓縮後直接消失）。不確定就**用一支短片在目標媒介上看過再決定**。
- vision 講「變清晰了」**不可當證據**（品質／美醜它不是裁判）——**可不可感只有人眼＋目標媒介算數**。
- 心法：驗收尺度要跟「誰在哪裡看」匹配，跟 §3「門檻要跟素材來源匹配」是同一族。

### 🔴 升頻不是免費加分：判定看**母材本身**，不是看升頻工具

實測（RTX Video Super Resolution 的檔案處理 lane）：

- 🔴 **升頻會把母材的缺陷一起銳化放大**（塑膠感、臉型漂移只會更明顯）→ 對**已知有臉部缺陷**的段，升頻前先做同尺寸對照片給人判，**不要自己決定要不要升**。
- **母材太爛會被直接拒收**：VSR 有**短邊 ≈360 的下限**（324p 退件 `unsupported_video_resolution`）→ 「爛母帶能不能救」有一半是工具先幫你回答了。
- **360p 以上救得起來的前提是「五官沒變形」**：母帶可以糊，但**歪嘴／大小眼**這種五官走鐘救不回來。
- **輸出必須與母材精確等比**：目標用**整數倍**算（`864×480→3888×2160` ×4.5、`1280×704→3840×2112` ×3）；四捨五入造成比例不符會直接退件。短邊 ≤2160、單邊 ≤4096、只能放大不能縮。
- ⚠️ **檔名一律 ASCII**：帶中文的檔會吃 `unsupported_container`，甚至「送件成功、跑到一半才 failed」（後者最難抓）。
- 速度 ≈ 或快於即時；✅ **音軌原樣保留**。

**量「升頻值不值得」的對照法（可重用）**：同一個鏡頭、同一秒做 N 級母材（例：360p／432p／480p／704p），各自升到自己的合法上限 → **每級各裁同一區塊、全部縮到同一個顯示寬度**，排成 [母材 | 升頻] 對照。⚠️ 顯示寬度要一致，否則比的是「誰的圖比較大」不是「升頻帶來什麼」。

**🔴 短暫的動態瑕疵（眨眼怪、眼睛走鐘）不能用靜圖下結論**：靜圖看不出「只有兩三格的異常」，稀疏抽樣也會剛好跳過它（同 §1）。
交付形狀＝① **編號接觸表＋時間對照表**（讓人直接指「第幾格／第幾秒」）② **原版 vs 升頻版的同尺寸上下疊片**（同一時間軸、兩邊都看得到那一瞬間）。

## 5b. 🔴 「它有沒在講話？」——交件前的自動守門

**症狀**：生成式影片會自己演「角色在講話」——嘴巴張合＋聽得懂的亂語。
除錯時對方只會說「多講了幾個不明意義的句子」，但**抽格看得到嘴巴在動**（同一件事的畫面證據）。

**檢測（三行）**：
```bash
ffmpeg -y -v error -i X.mp4 -vf "select='not(mod(n\,8))',scale=240:352,tile=4x4" sheet.png   # 16 格＝0,8,…,120 幀
# 再把 sheet.png 丟給本地（或輔助）vision 端點
# 問法：16 格拼圖 4x4，左上→右下依序是第 0,8,...,120 幀。只回答：哪幾格嘴巴張開或在說話？沒有就說全部閉合。
```
- 走**獨立的 vision 端點**（與主對話模型解耦）→ 工具職責分開，主模型不會因為同時要扮演角色而被工具任務干擾。先 `--ping` 確認回來 200。
- 🔴 **坑（必記）**：若該模型是 **reasoning 模型**——`max_tokens` 太小（實測 120 → 空字串、400 偏緊、500 起正常）→ **`content` 回空字串、答案全卡在 `reasoning_content`**（`finish_reason=length`）→ 看起來像「沒回答」。給 **2000**，且 `content` 空時回退讀 `reasoning_content`。
- 問法要小：**只問嘴巴**，不要叫它描述美感／其他（會把 token 吃光）。
- **雙向驗證才算數**（同一支片的兩個版本）：閉嘴版 → 「全部閉合」；有講話的版本 → 具體指到 48/56/72 格。只用正向樣本驗不過誠意，儀器可能對什麼都說「全部閉合」。

**定位**：這是**自己交件前的守門**（擋掉一看就壞的片），**不是取代人的目視驗收**（§5）。
**治本不在 QA 在產線**：把聲音欄位寫滿（正向描述環境音、配樂寫 N/A）才能讓它不生語音；或換不生語音的引擎。

## 6. 批次生產運維（避免白燒點數／工時）

- **斷點續跑**：每支完成就寫進 log JSON，重跑時「已存在且 > 門檻大小」就 skip。批次中斷、服務商卡住都能接，**不會重複計費**。
- 🔴 **「沒吐檔」不等於失敗**：服務商卡在 RUNNING（甚至 `contentType: unknown`）的任務**可能還在跑**——實測一支停批後約 35 分**自己變 COMPLETED**，成品好好的。收工前把沒吐檔的 gid 回頭再 query 一次。**申訴（`feedback`）之前先 query**，不然冤枉服務商、又白丟一支已經做好的片。
- 🔴 **服務商的結果 URL 常有壽命**（有的只有 **24 小時**）→ 查到 COMPLETED **立刻下載**，隔天就沒了。
- 🔴🔴 **服務商常沒有「列出歷史作品」的 API** → **作品清單只存在本機帳本**（跨機／重裝／別的 agent 跑的不會同步）。所以「訂閱到期／換帳號前把之前做的素材全抓回來」的正解是：① **先盤點本機與共享區已交付的成品**（逐支 ffprobe＋sha256 清單）——已擁有的不要重抓；② 缺的才回本機帳本找 gid；③ 都沒有就請使用者自己登入**服務商網頁的作品頁**查看／下載。**不要**拿「帳號要到期」當理由去猜／拼 URL。
- 🔴 **「安全內容一定過」不成立**：同一批圖的審查尺度會**浮動** → 一律**先送看看**；上傳階段被擋＝**0 費用**。
- **下載走官方欄位**——**不要用猜的 URL**（曾抓到 13-byte 錯誤檔）。
- **一次送一支、跑完再送下一支**（佇列紀律），不要並發搶自己機器的佇列。
- 長等待不要用單一超長 sleep；若要用 sleep 迴圈，注意工具的**前景硬超時**（超過就吃錯誤訊息，非任務失敗）。
- **產物全部落一個 outdir**，前綴區分批次（`idle_*` vs `*_to_*`），交付時才好對照。
- 🔴 **送付費任務前，先把「這一支實際餵了哪兩張圖」印出來對帳**（路徑＋sha256＋來源是哪一包），再用視覺確認那兩張真的是同一角色／同一專案 → 才 submit。共用目錄裡的舊圖被誤餵＝畫面「變身」，這種錯**不會有任何報錯**，錢先扣掉才發現。交付訊息與 log 都要記這兩個 sha。
- 🔴 **背景程序的「完成通知」可能晚很多才到，而那時檔案早就被你的修正版取代了**：通知本身**不是「檔案被蓋掉」也不是「要重跑」的證據**。收到通知的標準動作＝**驗檔**：`ls -la --time-style=+%H:%M:%S <檔>` 看時間戳 ＋ 對 manifest 的 sha256 —— 一致就直接回報「沒問題、無需動作」；只有真的不一致才處理。
- 🔴 **本機佇列被別人佔用時，批次腳本可能「跑完但沒下載」而靜止在那裡**（任務在伺服器 `/history` 裡是 success、本機卻沒有檔）。處置：**直接從 `/history` 把成品抓回來，不要重跑**。
- 🔴 **長秒數的批次不要跟前景指令綁在同一支呼叫裡**：超過工具前景上限會被「提升成背景程序」——直接 `background=true, notify=true` 起跑，然後去驗收別的項目。
- 🔴 **圖片差分批次同理**：一次工具等待內跑不完全部（本機約 7 分鐘）→ **一次只跑一個狀態 key**，且腳本要內建「**輸出檔已存在就 skip**」。被逾時砍掉留下的孤兒圖，**用同 key／同 seed 重跑補齊最省事**。
- 🔴 **批量驗收用一支腳本一鍵出表，不要手動逐支看**：逐支印「規格／有無音軌／動作峰值@幀／均值／首末差／跳接／閉環 SSIM」＋判定（⚠️ 集中在表尾）。**批次影片交件前先跑它**。
  （⚠️ 解析子程序輸出的 regex 要對得住實際字串——**驗收腳本自己也要先驗**。）

### 🔴 微動/idle「到底能不能循環」要用**接縫比值**量，不是用 SSIM 絕對值

- ❌ 錯的問法：「首尾 SSIM 0.90 算不算閉環？」——SSIM 會被顆粒/對比帶動，沒有可比的基準。
- ✅ 正解：**接縫比值 = 首尾幀差 ÷ 片內相鄰幀差的中位數**
  - `≈1` ＝接回去跟片內一樣順（看不出跳）；`>3` ＝每圈都會看到跳
  - 實測 14 支雲端 idle **全部 10.5~24.9（平均 18.3）→ 沒有一支真的閉環**（就算首尾 SSIM 看起來 0.90~0.97 很接近也一樣；呼吸/晃動會累積性漂移）
- **零成本解法：ping-pong（前段＋倒播段）**，閉環是數學保證的：
  ```bash
  # 前 h 幀（h=nb/2）＋ 第 1..h 幀倒播 → 總長不變、接縫只差 1 格
  ffmpeg -i in.mp4 -filter_complex \
    "[0:v]trim=end_frame=$h,setpts=PTS-STARTPTS[a];\
     [0:v]trim=start_frame=1:end_frame=$((h+1)),reverse,setpts=PTS-STARTPTS[b];\
     [a][b]concat=n=2:v=1[v]" -map "[v]" -c:v libx264 -crf 16 -pix_fmt yuv420p -an out.mp4
  ```
  ⚠️ **倒播段要排到「第 1 幀」為止**，不是排到中間（排錯的話接縫落在一半，比值降不下來）→ 實測比值從 10.5~24.9 降到 **0.68~2.23**（接縫差 ≈0.1~0.45 灰階，看不見）
- **兩種 ping-pong 要分清楚**：

  | 版本 | 做法 | 長度 | 代價 |
  |---|---|---|---|
  | 全動作版 | 正播全部 N 幀 ＋ 倒播第 N-1→1 幀 → 共 2N-1 幀 | **10 秒（翻倍）** | 無，動作完整 |
  | 半動作版 | 正播前 N/2 幀 ＋ 倒播回第 1 幀 → N 幀 | 5 秒（不變） | **後半段動作被丟掉** |

  - **播放速度兩版都一樣**（不是快轉）；差別只在「有沒有砍掉後半段動作」
  - 微動這種呼吸/晃動用哪版都行；**要完整動作就用 2N-1 幀版**
- 適合 ping-pong：呼吸/晃動/發呆這種微動；**不適合**：有方向性的動作（走路、開口講話）
- 🔴🔴 **「尾巴幾幀好像還是有點跳格」先鑑別「片內跳幀」還是「接縫落差」，不要反射性裁短**：
  量**末幀 vs 首幀差**再跟**片內相鄰幀差範圍**比——末幀差明顯大於片內相鄰差（實測 **1.01 vs 0.12~0.27**）＝那是**接回那一瞬間**在跳，**不是尾部內容壞**。此時裁短是反效果：尾幀跟首幀的相似度本來就隨時間**單調遞增**，越裁越對不上。正解＝**ping-pong 重組成閉環**（實測 1.01 → **0.22**）。
- 🔴 交付形狀：來源目錄會同時躺著**單向版**與**閉環版** → 檔名一定要能分辨（`_loop_` 之類）並在打包時以「出處 sha256」把關，否則抓錯檔＝尺寸／fps／幀數全對、**只有循環時會跳**（靜默失敗）。

### 🔴 動作均值 <0.10 要看姿勢：躺姿／靜態天生低

- 實測：**側躺躺姿 idle 均值只有 0.07~0.10**（站姿 idle 為 0.18~0.28）——因為躺著只剩呼吸起伏。
- 判準：**先看視覺**（有沒有做到微動），不要只看數字就重抽。
- 真的「完全不動」（帧間差≈0、影片跟靜圖一樣）才算失敗。數值只是第一道篩。
- 🔴 **不要把「動作型往返片」的門檻（32×32 逐幀差 1.5）拿來槍斃 idle 微動**：idle 本來就只有呼吸級。
  實測 12 支 idle：新片峰值 **0.18~1.17**；**已過關的舊 idle 只有 0.18~0.30** → 新片反而比驗收過的舊版更大，全部低於 1.5 是完全正常的。
  🔴 正確做法＝**跟「同一條產線已過關的舊 idle」對照**（同一個 ffmpeg 配方量舊檔），不是套絕對門檻。

### 🔴 閉環門檻要**分 lane**

|來源|幀數／尺寸|閉環 SSIM 實測|門檻|
|:--|:--|:--|:--|
|**雲端直出**|**121 幀**、原生高解析|**0.84~0.89**（5 支：0.840/0.851/0.864/0.874/0.884）|**≥0.82**|
|**本地低解放大**|124 幀|0.94~0.97|≥0.96|

- **成因**：雲端是原生解析度直出、每格帶獨立顆粒；本地是低解放大 → 顆粒被磨平 → SSIM 天然高。
- **不要用本地 lane 的 0.96 去量雲端** —— 5 支全被誤殺，而抽首/尾幀給眼睛看＝**明明一模一樣**。
- 心法同「過渡片不能比閉環」：**門檻要跟素材來源匹配**，不是拿一個數字套全部。

### 🔴 單格突變（跳幀）：要抓「孤立尖峰」，不要只看最大值

看「全片最大相鄰差」的腳本會漏掉單格突變（一格爆掉、但峰值不如快動作片高），也會冤枉快動作片。**判準是「孤立性」，不是大小**：

逐格平均差 → 取**中位數**當基準 → 標出 **> 4×基準** 且 **> 3×鄰居中位數** 且 **≥ 絕對下限 1.0** 的尖峰。
```bash
python3 scripts/check_frame_pops.py <檔或目錄> [--size 64x88] [--ratio 4] [--neighbor 3] [--abs-floor 1.0]
```
🔴 **靜止／慢速片要用 `--abs-floor` 這條**：整片中位數會是 0，只看「幾倍中位數」會讓「靜止畫面中插一格壞幀」永遠回報乾淨（舊版真的這樣漏報）。現在中位數為 0 時基準改用「鄰近中位數」，再由絕對下限擋掉壓縮雜訊。
🔴 **單格閃爍會留下「相鄰雙尖峰」（進一個、出一個）——鄰居一定要用中位數，不能用平均**：用平均的話另一個尖峰自己就是鄰居，`v > 3×平均` 這條會讓兩個尖峰互相豁免 → 整片靜止中插一格壞幀 100% 漏報（實測 50 格全黑插一格全白、最大差 255，舊版照樣回「✅ 無孤立尖峰」）。改成中位數後同一個案子會正確報出 `幀24→25` 與 `幀25→26` 兩個尖峰，並標「相鄰雙尖峰＝單格閃爍」。
  - 判讀：**成對（p, p+1）＝中間那一格被換掉**（閃一格）；**只有一個尖峰＝切了沒回來**（轉場／接縫）。
- 只看「最大」會誤判：某支 idle 峰值 5.65 但**鄰格也高**＝真動作（被正確濾掉）；真突變是 **16.15 而鄰格只有 1.45（13 倍）**。
- 🔴 **索引要精確**：把突變的兩格記錯一格（85→86 記成 86→87），後面抽幀、看圖、下結論全跟著錯，甚至判成「沒問題」。**拿同一對幀號再抽一次圖就會露出來**。
- **中彈處置**：抽出那兩格算 **4×4 區塊差**——「**每一塊都在跳**」＝整格被重繪／硬切（不是局部動作）→ **隔離該支（移到 `_defect/` 子目錄）＋換 seed 重跑**，不要混進交付。
- ⚠️ **端點貼合合格不代表中間沒壞**：這類瑕疵的首幀/尾幀可以都是 0.99 —— 兩組 gate 都要跑。

### 🔴 連續型的「場景／取景階躍」（家具被推走）——量法與判讀

**症狀**：不是「閃一格」，而是**後段整片慢慢滑走**（「把沙發扶手撞到位移了」這種講法）。`check_frame_pops.py` 抓不到（沒有突變）、端點貼合也合格（首尾都對得上）→ **要專門量**。

**量法：挑一塊「角色永遠碰不到」的區域，量它逐格的偏差＋逐格步階**
```bash
python3 scripts/check_region_step.py X.mp4 --region 0.86:0.98,0.06:0.20
```
- `dev[i]`＝該區塊與第 0 幀的平均絕對差；`step[i]`＝`|dev[i]-dev[i-1]|` 的最大值
- 🔴 **要看 step（步階），不要只看總量**：總量會被「她自己的身體伸進區塊」污染（實測躺姿時地板/沙發角區的 55.0／25.8 **全是她的腿**）；**純白牆角落**才是乾淨地標
- **判定不看絕對值、看「跟同批好檔比」**（本批 1188×1740、160×220 灰階實測）：好檔 **step ≤0.5**、後段漂移 **1.3~2.8**｜壞檔 **step 2.9~10.8**、後段漂移 **11.6~14.5**
- 🔴 **「連純白牆都一起跳」＝整格取景在動**（不是家具自己滑）——取景階躍與家具位移在畫面上長得一樣，只有「牆是否同時位移」能分開

**修法：改 prompt 沒用，要改圖**
- ❌ 實測無效的兩招（都試過、都重跑過）：目標句「沙發鎖死／不要被推動」，以及「主體往左挪＋鏡頭跟隨人物」（鏡頭跟隨在**原地動作**上反而多出一個慢速平移，後段漂移 11.6）
- ✅ **唯一有效：把目標圖重做**（差分時加激「家具整體位置/牆面/地板與光線不變」）→ 用同一個白牆角落指標選圖（舊 12.1 → 中選 0.8）→ 重跑影片：**step 10.8 → 0.5**
- 這條與「母圖與狀態圖必須同一佈置」是同一族：**兩端圖的幾何不一致時，模型只能靠位移去對齊**；差別在「道具不同」（憑空生成）vs「幾何不同」（整體滑走），**都不是 prompt 能修的**

**連帶規則：換掉任何定稿圖 ⇒ 以它為端點的產物全部過期**（idle＋過渡＋其反轉版）。端點 gate 會直接點名（實測 stale 的 idle 首幀只有 **0.8196**，正常 0.99）→ 別憑印象列清單。

**回程片（姿勢→母圖）＝ `ffmpeg -vf reverse`**（0 成本、接點完美）：首幀＝姿勢圖、尾幀＝母圖，實測 14/14 端點 0.982~0.992。⚠️ **只適用原地肢體動作**；跨場景走路倒轉會變倒著走，要各自生成。⚠️ 反轉**不修任何瑕疵**（pops／家具位移照樣留著，只是時間反過來）→ 先驗乾淨正向片再做反轉。

### 🔴🔴 兩個「靜默失敗」陷阱

1. **尾幀索引不可寫死**：舊版寫死 `select=eq(n\,123)`（本地 124 幀慣例）。拿去量 **121 幀的雲端片** → 抓不到 → ffmpeg **不產檔也不報錯** → 下一步比對時讀到**上一支留下的殘檔** → 報出**假的 0.6417**（真實值 0.8838）。
   → 正解：**用該檔自己的 `nb_frames-1`**，且比對前**先刪暫存檔**。
2. **所以：驗收數字怪怪的，先拿 ffmpeg 原生指令對照**（`ffmpeg -i a.png -i b.png -lavfi ssim -f null -`），一次就能分辨「素材真有問題」還是「腳本在說謊」。**假陽性（誤殺好素材）跟假陰性一樣貴**，而且更難發現。

### 🔴 過渡片不能用「閉環」判

批次驗收腳本的預設判準（閉環 SSIM ≥ 0.96）是給 **idle（同圖首尾幀）** 用的。
**拿它量過渡片（首≠尾，尾幀是另一張母圖）會 100% 誤殺**：實測 10 支全被標「⚠️ 閉環<0.96」，分數 0.64~0.69——那是「首尾本來就不同」的**必然結果**，不是瑕疵。

**正解：`--mode=trans`**（判準換成「這支片本來要達成什麼」）
- **首幀 vs 來源母圖**（起手貼不貼）→ 實測 0.92~0.945 ✅
- **尾幀 vs 目標母圖**（落點準不準，過渡片唯一真正重要的指標）→ 實測 0.90~0.924，整批一致即可
- **跳接**仍是硬指標 → 實測真的抓到 2 支缺陷（峰值 43 的硬切，非 idle 的那些 1.6~9.7）
- 比較時**兩邊要先縮到同一尺寸** → 都 `scale=594:870` 再算 SSIM。

**心法：驗收門檻要跟「這支片原本要達成什麼」匹配；拿 idle 的尺量過渡＝全部誤殺，報告會失真。**

### 🔴 更上層的前提：母圖與狀態圖必須「同一佈置」——不然過渡根本不用做

過渡片（A 狀態圖 → B 母圖）能不能做，**動手前先逐項比兩張圖**：牆面／地板／光線／**家具位置**／**桌上道具**。
實例：沙發坐姿母圖**桌上有一台平板**、人坐沙發右緣；其他狀態圖**桌上空的** → AI 補不出「憑空冒出的平板」或沙發位移，**這系列過渡必跳**（實測那兩支跳接峰值 43，同期其他過渡只有 1.6~9.7）。
**這不是 prompt 問題，是素材前提不成立**——別花時間改 prompt、換模型、換 seed。

檢查法（一次性做完）：拼左右對照圖再問 vision「兩邊場景/道具是否一致」
```bash
ffmpeg -y -v error -i A.png -i B.png -filter_complex \
  "[0]scale=400:585[a];[1]scale=400:585[b];[a][b]hstack" pair.png   # 多組就用多個 hstack 再 vstack=inputs=N
```
**結論：母圖與狀態圖不同佈置 → 該系列過渡一律砍掉，只出 idle**（idle 是同圖首尾幀，沒有這個問題）。交件前先講清楚這條，比事後被抓「畫面一定會跳」好。

### 🔁 補跑／重跑紀律（驗收 → 修正迴圈）

**1. 先對帳，再決定補什麼。** 執行 log 收尾寫「完成 N/N」**不等於**磁碟上有 N 支產物——批次中途遇到 `ConnectionResetError` 之類的失敗，log 仍可能漂亮收成整數（實測 10 支排程跑完、實體少 1 支）。唯一可信的對帳是**「腳本宣告的清單」vs「磁碟實體檔」**。
→ 少掉的那支就是補跑清單；**不要只信 log 或信「上次跑過了」。**

**2. 🔴 補跑同一支，一定要換 seed。** 這些腳本的 seed 是 `SEED0 + 索引` 的**固定值** → 直接重跑會**一毫不差地再現同一個瑕疵**（同 seed＝同結果），跑完只會誤判成「這支修不好」。
```bash
python3 gen_idle.py --seed-offset 50
```
實測：動作均值 0.07（木頭級）→ 換 seed 後 0.11，直接過關。**換 seed 是補跑的第一手段，不是改 prompt、不是加參數。**

**3. 重跑前先封存舊版**，不要刪、不要原地覆蓋：`mkdir -p _v2_<原因> && mv 舊檔 _v2_<原因>/`。
- 對方很可能說「舊的其實可以」→ 檔案還在，一句話就能放回去。
- ⚠️ 封存子目錄**不要**落在驗收掃描範圍內：`ls $OUT/*.mp4` 不遞迴所以安全，別用 `**/*.mp4` 或任何遞迴掃描同一層，否則封存檔會被當新產物重複計數。

**4. 連帶產物要一起重生。** 倒轉檔（`*_reverse.mp4`）是從本體 `-vf reverse` 生的：本體換 seed，倒轉檔**必須一起重生**，否則新本體＋舊倒轉＝接不起來。腳本會自動重生，但**前提是你先把舊的本體跟舊的倒轉檔都移走**——不然會被「已存在就 skip」跳過。

**5. 重跑後同一組 gate 全部重跑一遍**：規格／音軌／動作量／跳接／（idle）閉環／（有語音風險的）嘴巴守門。只驗「剛剛修的那一項」不算過關——**換 seed 是換一整支片，別的指標也會跟著變。**

| **微動跳回起始姿勢不連續** | 微動片沒閉環 | 本地用「同圖首尾幀」（天生閉環）；雲端片用倒轉接片（§4c） |
| **補跑／重跑後還是同一個瑕疵** | seed 固定 → 同 seed 同結果 | 帶 `--seed-offset` 換一顆 seed；並先確認舊檔已移走（否則被 skip） |

| **背景牆的陰影會變／最後整塊變成灰牆面** | 首尾幀牆面不同源（差分改過動作 → 模型重畫陰影） | 先把尾幀牆同步成首幀（§4e）**再重跑**，重抽圖沒用 |
| **播到一半畫面突然「閃一下」／某一格整張跳掉** | 模型單格重繪／硬切（端點驗不出來） | `check_frame_pops.py` 抓孤立尖峰 → 隔離該支＋換 seed 重跑（§6） |
| **家具／扶手被「推」位移、畫面整體滑走**（連續型，不是突變） | **目標圖的場景幾何與來源圖不一致** → 固定鏡頭只能把場景滑過去對齊（**不是 prompt 問題**） | 用**她碰不到的白牆角落**量「逐格步階」（§6 場景階躍段）→ 重抽那張目標圖再重跑 |
| **stale 產物：首幀對不上定稿圖**（約 0.82、正常 0.99） | 那張定稿圖**後來被換過** → 以它為端點的產物全過期 | 以「端點 gate」掃出過期清單 → idle＋過渡＋其反轉版一起重出（§6 場景階躍段） |
| **回程（姿勢→母圖）要另出一支嗎** | 原地肢體動作的「回去」＝原片的時間反轉 | 直接 `ffmpeg -vf reverse`（0 成本）；**只適用原地動作**（§6 場景階躍段） |
| **回程片裡服裝／物件「自己復位」** | 去程終點比基準更鬆 → 回程只被兩端約束、沒被要求演動作，模型就把差異憑空抹平 | 回程 prompt **明寫補償動作**（§4g） |
| **運鏡詞怎麼改都無效：角色一律往她的左前方走** | 首尾幀**不同空間** → 物理連續性優先，運鏡指令被忽略 | **不要再調詞**（試過 5 版全敗）→ 換有內建運鏡控制的雲端模型、或重出同場景同機位母圖（§4f） |
| **整個畫面歪掉（地平線斜）** | 運鏡詞寫了 `rotates clockwise` 之類 → 被吃成 **roll／Dutch angle** | 改寫 `pans horizontally to the right` ＋護欄句 `The horizon stays level...`（§4f） |
| **多段續接的接縫處「手裡的東西」突然消失／多出來** | 續接機制只約束人物／場景／光，**物件狀態不在它的視野內** | 產線端避開「會讓物件出現／消失」的劇情設定；驗收時在每個接縫左右各抽數格盯手上的東西（§1 密度） |
| **想用升頻／修臉救畫質** | 需求沒對齊觀看媒介（手機／社群壓縮吃掉像素級差異） | **先確認最終在哪看**再用一支短片試（§5 升頻段） |

## 8. 🔴 測模型能力＝測大幅動作，不是靜態片

「這種靜態影片跑完效果看起來還可以，只是沒啥動作，**測影片要測的是大幅運動變化**，比如戰鬥場面、跳舞、施展魔法、人物移動、大幅改變姿勢、說台詞之類的才看得出來效果。」

- 靜態／微動片只證明「**不壞**」（不崩、不漂移、不變形）；**證明能力要靠大幅動作**
- 固定六類壓力測試：
  1. **戰鬥**——拔劍（快動作）→ 低角度前衝橫斬／旋身格擋（大幅位移＋快切）→ 特寫收尾
  2. **跳舞**——連續旋轉、裙襬整片甩開、手臂大幅掃過頭頂
  3. **施展魔法**——聚能 → 地面符文亮起、光束上炸、落葉塵埃螺旋上升 → 白光閃過
  4. **人物移動**——朝鏡頭走 → 小跑跨過障礙 → 身體貼鏡頭經過 → 停步回望
  5. **大幅改變姿勢**——蹲低 → 一氣起身 → 拉弓（弓身明顯彎曲）→ 放箭（後座力震全身）
  6. **說台詞**——抬眼直視鏡頭 → 開口 → 停頓再看回來（對白標記＋嘴型＋音軌）
- 寫法：一支 **10 秒**、切 **2–3 個 shot**，**時間軸寫死**（0／3.5／7 秒）＋每段寫鏡頭（cut／pull back／arc／tracking）——只寫「她跳舞」模型只會微動；參照圖只給身份，**時間與鏡頭變化不寫就不會有**
- 驗收看 **前 1/3 vs 後 1/3 是否一致**：後段暴增＝失控加速（實測一支 2.43→3.19＝+31%，判輕微漂移）
- 這組六類可以直接當**新模型／新產線的開箱驗收包**

### 同素材 A/B 測新產線（可重用）
1. **同一張參考圖、同一份 prompt、同一顆 seed**（不同引擎的 seed 不通用沒關係，控住前三項才是重點）
2. 兩邊輸出**對齊長度**（例：本地 194 幀≈8.08s ↔ 雲端 `duration_seconds: 8`）
3. 量四件事：解析度／動作量（平均相鄰差＋前後段一致性）／音軌（stream 存不存在＋`volumedetect`）／成本與耗時
4. 數據只講到「活不活、穩不穩」；**臉有沒有跑、質感順不順＝交人目視**（§5）

## 8b. 🔴 動作片分鏡的四個護欄（多段、但全片只有一次「結果」）

**1. 每段界線要寫「此刻還沒做什麼」**
只寫「做了什麼」時，模型會**提前把後面段落的動作演完**，下一段又叫它做一次 → 影片出現**兩次同樣的動作**。
- shot 1 收在 `...held ready - the string is still relaxed; nothing is drawn and nothing is fired in this shot`
- shot 2 收在 `...the string is drawn and held, and she does not loose it in this shot`
- summary 全域宣告：`contains exactly one release - she releases only in the last shot; no shot may repeat an action that has already happened`
- 同機制可套：開一槍、砸一次、跳一次、簽名、拔刀——**任何「結果只能發生一次」的動作**

**2. 秒數要對得起動作量；「切掉動作」也算**
動作實際 7 秒卻排 10 秒、或把「走過去取道具」那整段砍掉 → **空出的預算會被拿去重複動作**（模型自己在段落尾先偷做一次）。
- 🔴 **結構解：單次結果動作之後讓鏡頭離開主體**——甩頭追著箭飛走、主體不再入鏡，就**沒有再重複一次的機會**；同一個鏡頭還順便滿足了「尾巴要有結果畫面」的需求
- 備選：把總長砍到「動作量＋一點餘裕」（例：動作 7 秒 → 8~9 秒）、或把動作排緊補回空檔

**3. 方向一條線**
聲音來源 → 視線 → 轉身的側 → 武器位置 → 瞄準 → 出手方向、**以及目標物**，全部同一個畫面側。
- prompt 要**畫面側＋身體側都寫**（例：`the right side of the frame - her left`）——只寫一邊會漂
- 動作順序也要順著這條線：**轉頭 → 整個人轉向該側 → 才召喚／舉武器**，不要正面站著斜射

**4. 目標物要同軸，而且前段藏住**
目標若一開始就尷在背景，會跟主體的站位／方向對不上（看起來像站著亂打）。
- 前段**完全看不到目標**（遮擋物＋只有聲音）→ 留給「鏡頭追尾」那一鏡揭曉；先露臉就沒有揭曉感
- 明寫同軸：`her body, her bow arm and her gaze all point along one single line toward the right side of the frame, where the sound came from`
- **過肩視角**（鏡頭從她背後望向目標那側）讓觀眾視線跟她同一條線，追尾鏡頭接上去才順
