# 長篇小說寫作 Skill

用章節制協助使用者寫繁體中文長篇（數萬字以上）。一次只產出 1 章正文，並維護可重用的記憶卡，避免把整本書塞進 context。

預設文體：自然敘事、人物行為符合設定、不說教。題材與尺度依使用者指示處理。

不要用這個 skill 一次生成整本書。不要把舊章全文反覆貼回 prompt。

## When to Use

- 使用者要寫長篇、連載、幾萬字小說、章節正文
- 使用者要大綱、細綱、角色卡、章節摘要、文風對齊
- 使用者說「寫下一章」「接上一章」「整理進度」

不要用在：短詩、單篇極短篇、純校對、純翻譯（除非使用者明確要求把本章譯成別的語言）。

## Prerequisites

開始寫正文前，先確認或補齊這 5 項。缺的就先問，不要猜整本設定。

1. 書名
2. 類型／調性（例如都市懸疑、成人向、冷靜疏離）
3. 視角（第一人稱／第三人稱有限／全知）
4. 主角與關鍵配角（各一行即可）
5. 目前進度摘要（300 字內）或「從第 1 章開始」

若使用者已有設定檔，讀檔後沿用，不要重寫世界觀。

詳細模板見 `templates/`。完整欄位說明見 `references/memory-card.md`。
跨章一致性（稱呼線／地點／時間軸／角色知識鏈）見 `references/cross-chapter-consistency.md`（併自原 `cross-chapter-consistency` skill）。

## Quick Reference

| 指令意圖 | 產出 |
|---|---|
| 開新書／建檔 | `templates/bible.md` 填空版 |
| 寫總大綱 | 3～5 卷，每卷 5～10 個主事件 |
| 寫細綱 | 單章 5～8 句，含目標、衝突、結尾鉤子 |
| 寫本章正文 | 2500～4000 字，直接正文，無前言 |
| 寫完收尾 | 100～200 字章節摘要 + 更新進度摘要 |
| 對齊文風 | 先要 1～2 段範例，再寫 |

建議生成參數（若後端可設）：敘事 `temperature 0.72–0.80`；要穩一點 `0.65–0.70`；對話偏活 `0.80–0.88`。

## Procedure

### A. 開新書

1. 用 `templates/bible.md` 建立專案聖經。只填已知欄位，未知標「待定」。
2. 先寫總大綱，再寫第 1 章細綱，得到使用者確認後才寫正文。
3. 問清禁忌（不能出現的情節、不能死的角色、不能破的世界規則）。

完成標準：聖經檔有書名、類型、視角、主角、第 1 卷主線。

### B. 寫單章正文

1. 讀取本章細綱。沒有細綱就先寫 5～8 句細綱請使用者確認。
2. 組裝寫作 prompt，只帶這些，不要帶全書：
   - 系統角色（短）
   - 固定記憶（書名／類型／角色卡精簡版／世界觀重點／進度摘要 ≤300 字／上一章結尾）
   - 本章任務（目標、必出現、禁止、字數、視角、文風）
3. 直接輸出正文。禁止「好的，我來寫本章」、禁止大綱複述、禁止章末解說。
4. 正文結束後另開一段，輸出：
   - 本章摘要（100～200 字）
   - 更新後的「目前進度摘要」（仍 ≤300 字）
   - 角色狀態變更（有變才寫）
   - 下一章建議鉤子（1～3 句）

完成標準：正文達標字數、人物沒有突然換性格、結尾有可接續的鉤子、摘要可單獨當下一輪記憶。

寫作 prompt 骨架見 `templates/chapter-prompt.md`。

### C. 連續連載

1. 上一章摘要取代「上一章全文」。
2. 進度摘要只保留仍會影響後文的事實，刪掉已消化的細節。
3. 角色卡只更新「目前狀態」，不要每次重寫外貌。
4. 每 5 章做一次「一致性檢查」：人名、稱呼、時間線、未回收伏筆。

### D. 改寫／續寫

- 使用者指定段落才改，不要整章重寫。
- 續寫時先複述本章最後 200 字作為接縫，再往下寫，避免語氣斷裂。

## Pitfalls

- Context 被舊章全文塞爆 → 只保留摘要 + 角色卡 + 上一章結尾。
- 人物說話變同一張嘴 → 每張角色卡必須有「說話方式」一行。
- 章節變成流水帳 → 細綱裡一定要有「本章衝突」與「章末鉤子」。
- 模型愛加說教或免責 → 系統角色寫明「不說教、不加免責聲明、不要複述大綱」；題材與尺度依使用者指示。
- 一次寫超過 4000 字容易失焦 → 拆成場面建立／衝突／收束三段。
- 繁簡混用 → 全文繁體中文，專有名詞保持使用者指定寫法。
- 把 MoE 模型當「不會忘」 → 它不會真的記住全書，記憶全靠你帶進 prompt 的卡片。

## Verification

寫完一章後自檢這 6 項，有一項失敗就先修再交給使用者：

1. 視角有沒有跳。
2. 角色名字、稱呼、關係有沒有跟角色卡衝突。
3. 時間線是否接得上上一章結尾。
4. 有沒有突然解決不該在本章解決的主線。
5. 正文是否真的是繁體中文。
6. 摘要是否短到可以當下一輪記憶（≤200 字）。
